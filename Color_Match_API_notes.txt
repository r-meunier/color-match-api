PART I
- CPU and memory usage is constant for the 2 million elements in the large data set.
- Performance improvement: Partitioning the data? // https://stackoverflow.com/questions/29107607/best-spring-batch-scaling-strategy
- ID generation type?
- Alternative for Batch processing: Apache Spark.
- Steps in Spring Batch can be processed in Chunks or in Tasklets. I used Chunks because of the complexity of the job (reading, processing items). ItemReader collects items into Chunks.
	Chunk size = commit interval.
- Spring Batch execution time, when Single-Threaded:
	N of Items * Item Processing Time = 1000000 * 1 ms = 1000000 ms = 1s = 16.7 mins 
	Single-Threaded: (499 items: Step: [step1] executed in 2s776ms)
	- Multi-Threaded: (499 items: Step: [step1] executed in 1s678ms) (chunk size: 100)
	- 200K records:  Step: [step1] executed in 1m3s883ms
	https://medium.com/@YounessBout/increase-spring-batch-performance-through-multithreading-b513ca90aeb5
- Thread safety?
- ThreadPoolTaskExecutor reuses threads!
	
- CONS IF MULTI THREADED: No restartability for the JOBs. If the JOB fails there is no way for it to resume. Also No order garanties for processing the items. You should account for thread safety (Example could be not using Cursor Based JDBC Item readers)
